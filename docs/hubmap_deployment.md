# HuBMAP processing and remote MCP deployment

## Goal

This page shows, with commands that can be re-run and records that can be
checked, two things done with KINTSUGI:

1. **End-to-end processing of public data.** A raw CODEX dataset from the
   [HuBMAP Data Portal](https://portal.hubmapconsortium.org) goes through
   stitching, deconvolution, extended depth of focus, registration and signal
   isolation on UF Research Computing's HiPerGator.
2. **Remote, authenticated AI-assisted analysis.** The KINTSUGI MCP server
   serves the processed project from a free cloud VM over HTTPS. Claude Code
   and a claude.ai custom connector drive signal isolation remotely.

Sections marked **Pending** are filled in from the actual run: job IDs, run
times, figures and session excerpts. Nothing in them is estimated or invented.

## Platform choice and cost

The constraints were a free tier, and UF-provided platforms where possible. All
the facts below were checked in November 2026; free-tier terms change, so
re-check them before relying on them.

| Role | Platform | Cost | Why |
|------|----------|------|-----|
| Processing | UF Research Computing **HiPerGator**, existing group allocation | No additional cost | UF-provided GPUs and `/blue` storage; the KINTSUGI Snakemake/SLURM workflow already targets it |
| MCP hosting | **Oracle Cloud Always Free**, Ampere A1 (arm64) | $0 | The only always-on free tier found that is large enough: 2 OCPU / 12 GB RAM / 200 GB block storage across the tenancy ([Oracle docs](https://docs.oracle.com/en-us/iaas/Content/FreeTier/resourceref.htm)) |
| Not used: UF RC **PubApps** | Public research web hosting | Needs a HiPerGator allocation and a support ticket; billed per year | UF's sanctioned way to host a public web service ([docs](https://docs.rc.ufl.edu/services/web_hosting/)). The better long-term home if the service becomes permanent |
| Not used: HiPerGator itself | — | — | Long-running services are not allowed on login nodes or as daemons ([usage policy](https://it.ufl.edu/rc/documentation/policies/hipergator-usage-policies/)) |
| Not used: UFIT public cloud (AWS / Azure / GCP) | — | Billed to a department chartfield | Not free ([UFIT](https://it.ufl.edu/hosting/services/public-cloud-services/)) |

Oracle's terms to keep in mind:

- An Always Free A1 instance can be **reclaimed when idle**: if, over 7 days, its
  95th-percentile CPU, network and memory use are all below 20%. Stop or remove
  the deployment when the demonstration is over (see [Teardown](#teardown)). Do
  not generate artificial load.
- Oracle requires a payment card at sign-up. The Always Free resources are not
  charged.

## 1. Download to HiPerGator

Raw HuBMAP files are distributed over Globus, not plain HTTPS. Work in your
group's `/blue` directory. `/home` is too small for this data.

```bash
ssh <gatorlink>@hpg.rc.ufl.edu
cd /blue/<group>/<gatorlink>
mkdir -p hubmap && cd hubmap
kintsugi hubmap info HBM283.GNGR.785
kintsugi hubmap manifest HBM283.GNGR.785 -o HBM283.GNGR.785.manifest.txt
```

Transfer the dataset with either option:

- **Globus web app (no extra software).** Open the dataset page
  (`kintsugi hubmap info` prints the portal URL), choose the Globus download
  link, and transfer the dataset folder to UF Research Computing's Globus
  collection, at `/blue/<group>/<gatorlink>/hubmap/`.
- **`hubmap-clt` (scripted).** This needs Globus Connect Personal running on
  the destination; see the [HuBMAP CLT docs](https://docs.hubmapconsortium.org/clt/).

  ```bash
  pip install hubmap-clt
  hubmap-clt login
  hubmap-clt transfer HBM283.GNGR.785.manifest.txt -d /blue/<group>/<gatorlink>/hubmap
  ```

Record the transferred size with `du -sh` (Pending).

## 2. Create and stage the project

```bash
kintsugi init /blue/<group>/<gatorlink>/KINTSUGI_Projects/HBM283_LN --name HBM283_LN --slurm
kintsugi hubmap stage /blue/<group>/<gatorlink>/hubmap/HBM283.GNGR.785 \
    /blue/<group>/<gatorlink>/KINTSUGI_Projects/HBM283_LN --hubmap-id HBM283.GNGR.785
```

`kintsugi hubmap stage` does the following:

- Finds the cycle directories (`Cyc1_reg1/`, `cyc001_reg001_*/`, ...) under any
  Globus nesting, and symlinks them as `data/raw/cyc001` … `cyc013`. The raw
  data is not copied. Use `--copy` to copy it instead.
- Translates the CODEX `experiment.json` (`numCycles`, `regionHeight`,
  `xyResolution`, ...) into `meta/experiment.json`, and keeps the original as
  `meta/experiment.source.json`.
- Copies `channelnames.txt` to `meta/CHANNELNAMES.txt`.
- Writes `data/raw/.staged` and `meta/hubmap_provenance.json`.

Check the staged metadata before processing:

```bash
cd /blue/<group>/<gatorlink>/KINTSUGI_Projects/HBM283_LN
cat meta/experiment.json meta/CHANNELNAMES.txt
kintsugi workflow config .        # writes workflow/config.yaml from meta/experiment.json
kintsugi workflow check .         # SLURM accounts and GPU availability
```

## 3. Process on HiPerGator

The Snakemake workflow runs stitching, deconvolution and EDF per cycle on GPU,
then registration, signal isolation and the QC rules:

```bash
kintsugi workflow run . --dry-run      # preview the DAG
kintsugi workflow run . --detach       # survives SSH disconnects
kintsugi workflow status . --watch     # live dashboard
```

When it finishes, `data/processed/signal_isolated/.snakemake_complete` exists
and the QC reports are under `data/processed/*/qc/`.

## 5. Deploy the MCP server on Oracle Cloud

### 5.1 VM

1. Create an Oracle Cloud account, and pick a home region with A1 capacity.
2. **Compute → Instances → Create instance**:
   - Image: Canonical Ubuntu 24.04 (aarch64).
   - Shape: `VM.Standard.A1.Flex`, 2 OCPU, 12 GB.
   - Boot volume: 100 GB.
   - Add your SSH public key.
3. In the instance's VCN **security list**, add stateful ingress rules for TCP
   80 and 443 from `0.0.0.0/0`. Port 80 is needed for the Let's Encrypt
   challenge and the redirect.
4. Oracle's Ubuntu images also filter traffic with `iptables`. Open the same
   ports on the VM:

   ```bash
   sudo iptables -I INPUT 6 -m state --state NEW -p tcp --dport 80 -j ACCEPT
   sudo iptables -I INPUT 6 -m state --state NEW -p tcp --dport 443 -j ACCEPT
   sudo netfilter-persistent save
   ```

5. Give the VM a DNS name. A free [DuckDNS](https://www.duckdns.org) subdomain
   pointed at the instance's public IP is enough, for example
   `kintsugi-demo.duckdns.org`.

### 5.2 Docker

```bash
sudo apt-get update && sudo apt-get install -y docker.io docker-compose-v2 git rsync
sudo usermod -aG docker "$USER" && newgrp docker
```

### 5.3 Copy the processed project

The server needs the project marker, the metadata and the processed images that
the tools read: `data/processed/registered/` and, to review results,
`data/processed/signal_isolated/`. Raw, stitched and deconvolved data stay on
HiPerGator. Run on the VM:

```bash
sudo mkdir -p /srv/kintsugi/HBM283_LN && sudo chown "$USER" /srv/kintsugi/HBM283_LN
rsync -av --progress \
    --include='kintsugi_project.json' --include='meta/***' \
    --include='data/' --include='data/processed/' \
    --include='data/processed/registered/***' --include='data/processed/signal_isolated/***' \
    --exclude='*' \
    <gatorlink>@hpg.rc.ufl.edu:/blue/<group>/<gatorlink>/KINTSUGI_Projects/HBM283_LN/ \
    /srv/kintsugi/HBM283_LN/
sudo chown -R 1000:1000 /srv/kintsugi/HBM283_LN    # the container's user
```

Check the size before copying with `du -sh` on HiPerGator. The 200 GB of
Always Free block storage is shared by every volume in the tenancy.

### 5.4 Start the server

```bash
git clone https://github.com/smith6jt-cop/KINTSUGI.git
cd KINTSUGI/deploy/oracle
cp .env.example .env
python3 -c 'import secrets; print(secrets.token_urlsafe(32))'   # put this in KINTSUGI_MCP_TOKEN
nano .env                                                       # PUBLIC_HOST, PROJECT_DIR
docker compose up -d --build
docker compose logs -f
```

`deploy/oracle/` contains:

| File | Purpose |
|------|---------|
| `Dockerfile` | Python 3.11 slim with libvips, `pip install ".[mcp]"`, a non-root user, and `kintsugi mcp start --transport streamable-http` serving `/project` |
| `compose.yaml` | The KINTSUGI container (internal port 8000 only, read-only root filesystem, no capabilities, 9 GB memory limit) and Caddy (ports 80/443) |
| `Caddyfile` | Automatic HTTPS for `PUBLIC_HOST`, reverse proxy to KINTSUGI with response buffering off (server-sent events) |
| `.env.example` | `KINTSUGI_MCP_TOKEN`, `PUBLIC_HOST`, `PROJECT_DIR`, `KINTSUGI_MEM_LIMIT` |

Check the server from any machine:

```bash
curl -s https://kintsugi-demo.duckdns.org/healthz                    # {"status":"ok"}
curl -s -o /dev/null -w '%{http_code}\n' -X POST https://kintsugi-demo.duckdns.org/mcp   # 401
curl -s https://kintsugi-demo.duckdns.org/.well-known/oauth-authorization-server | python3 -m json.tool
```

## 6. Connect the clients

### Claude Code (Bearer token)

```bash
claude mcp add --transport http kintsugi https://kintsugi-demo.duckdns.org/mcp \
    --header "Authorization: Bearer $KINTSUGI_MCP_TOKEN"
claude mcp list
```

In a session, `/mcp` lists the `kintsugi` server with its 34 tools, five
resources and the `signal_isolation_workflow` prompt.

### claude.ai (OAuth)

1. **Settings → Connectors → Add custom connector.** On Team and Enterprise
   plans, an Owner adds it.
2. Name: `KINTSUGI`. URL: `https://kintsugi-demo.duckdns.org/mcp`. Leave the
   OAuth client fields empty, because the server supports dynamic client
   registration.
3. **Connect.** The browser opens the server's `/login` page. Enter the value of
   `KINTSUGI_MCP_TOKEN`. claude.ai receives a one-hour access token, refreshed
   automatically for up to 30 days.
4. In a chat, enable the connector and ask, for example: *"Use KINTSUGI to list
   the channels, then isolate the CD31 signal using the matching blank channel,
   and show me the before/after thumbnails."*

Restarting the container signs every client out, because OAuth state is held in
memory. Reconnect from the connector settings.

## 8. Security model of the deployment

| Layer | Control |
|-------|---------|
| Network | Only 80/443 open; the MCP process listens only on the Docker network |
| Transport | TLS from Caddy (Let's Encrypt), HSTS |
| Authentication | `KINTSUGI_MCP_TOKEN` as a Bearer token, or OAuth 2.1 with PKCE: registration limited to claude.ai's callback and loopback, `/login` requires the same secret, lockout after 5 wrong attempts |
| Authorization | One user, one project: every `project_path` must resolve inside `/project` |
| Process | Non-root user, read-only root filesystem, `no-new-privileges`, all capabilities dropped, memory limit |
| Request hygiene | `Host`/`Origin` allowlist (DNS-rebinding protection), 4 MB request body limit, at most 8 concurrent MCP sessions |

The full description of the remote mode's controls is in
[MCP server → Remote mode](mcp.md#remote-mode-streamable-http). Rotate the
secret by editing `.env` and running `docker compose up -d`.

## Teardown

```bash
docker compose down              # stop; keeps the volumes and the project
docker compose down -v           # also remove the learning database and certificates
```

When the demonstration is over, terminate the instance and delete its boot
volume in the Oracle console, so it does not count against the Always Free
quota or get reclaimed unexpectedly. Delete the DuckDNS record.
